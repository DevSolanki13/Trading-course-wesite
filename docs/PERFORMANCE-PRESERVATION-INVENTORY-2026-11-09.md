# Preservation inventory and verification contract

Scope: finish local Phase 0-1 acceptance before changing media delivery in Phase 2. No live deployment, shared-database mutation, provider configuration, redesign, feature removal or dependency upgrade.

Planning policy: compact plan, dependency-level source inspection, impact-level verification; no delegation. Reasons: existing multi-file changes, browser/request boundaries and animation preservation. Allowed changes for this batch: measurement/preview scripts, browser verification/configuration, evidence documents, and a narrowly demonstrated Phase 1 defect if verification finds one. Phase 2 source/assets remain unchanged until the gate is recorded.

## Acceptance evidence required

- P0: environment and complete named inventory; production-mode captures including empty/loading/error; three labelled mobile samples per critical route with median/range; cold/warm browser-cache and first/returning video scenarios; separate public-data cache miss/hit probe; request/byte/API timing records and explicit metric definitions; trace/frame-interval evidence; baseline failures and route budgets.
- P1: deterministic lesson/order/polling regressions, inline enter/exit, keyboard and touch, both themes, reduced-motion stop/resume, unchanged carousel path/hover easing, explicit transitions, and a measured repaint review before changing visual layers.
- No Phase 1 speed gain is inferred from the new baseline: it is measured after core interaction fixes and before Phase 2. Invalid/incomplete Lighthouse runs remain diagnostic evidence only.
- Physical devices, live provider/DRM and hosted authentication acceptance remain explicit Phase 7 limits. Local acceptance never promotes fixtures to live-service evidence.

## Motion review boundaries

| Before                                                                  | After                                                                                 | Why                                                                                                 |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Frame-driven carousel transform plus CSS transform interpolation        | Existing frame loop alone owns placement; shadow transition remains                   | Avoid competing timing while retaining radius, speed easing, direction, depth and all card content. |
| Focused player controls could fade                                      | `:focus-within` keeps the controls visible                                            | Keyboard users retain visible feedback without changing pointer fade.                               |
| Unbounded `transition: all` in 23 declarations                          | Explicit intended properties at original duration/easing                              | Bound the transitions without deleting their hover/theme feedback.                                  |
| Detail content could disappear before exit or reopen from obsolete work | Per-row retained content, clipped padding, selection guard and transition-end cleanup | Preserve inline spatial continuity and interruptibility.                                            |

The animation review skill's generic GPU-only/deletion advice does not override the user's requirement: an inline accordion that pushes subsequent rows requires layout. Preserve the approximately 280ms grid expansion. Do not delete effects or replace this accordion with an overlay to obtain an artificial performance pass. Repaint profiling is evidence for a decision, not automatic authorization to strip blur/shadow/masks.
