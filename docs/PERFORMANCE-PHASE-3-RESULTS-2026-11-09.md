# Phase 3: fewer repeated requests and faster dashboard data delivery

Date: 9 November 2026

Status: **Engineering implementation and local non-browser verification complete. Browser/provider acceptance and signed-in navigation timing comparisons remain pending.** Phase 2 browser acceptance is still pending separately. No browser tools, Playwright or Lighthouse were run.

## What changed and why

| Area                         | Before                                                                                         | After / use                                                                                                                                                                                                                                                                                                                                  |
| ---------------------------- | ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Staff identity               | Shared provider and admin shell independently fetched `/api/auth/me`                           | Admin shell consumes the provider's verified display snapshot. Header/admin mounting test makes exactly **one** identity request, including structured device-limit/blocked/revoked errors and MFA gating.                                                                                                                                   |
| Identity freshness           | Provider refreshed on navigation/focus; admin kept its separate mount-time snapshot            | Shared navigation/focus refresh plus explicit refresh after profile updates. Path-specific readiness prevents rendering staff controls from an earlier route's identity. In-flight requests are shared, not globally cached.                                                                                                                 |
| Login/logout/account changes | Some logout paths did not clear shared state; no cross-tab invalidation signal                 | Successful session-changing form redirects and logout emit a timestamp/random invalidation signal only. Other tabs verify their own cookie session. Logout clears shared state, and stale replies cannot restore it. Failed logout responses do not falsely clear the shared identity.                                                       |
| Account isolation            | Student component could retain old local state until navigation                                | On a cross-tab change, immediately hide old-account UI and stop its billing/lesson work while verifying. Verified account mismatch triggers a server refresh; new account/initial destination gets a fresh keyed dashboard. Transient session errors show retry rather than old data; device-limit redirects are retained.                   |
| Server identity              | Repeat identity calls within a server render could repeat verification/profile reads           | React `cache` wraps identity within a render pass only. It is not a cross-request cache and does not deduplicate ordinary Route Handler calls. Admission/revocation, role/MFA and conditional activity updates remain enforced.                                                                                                              |
| Public assets                | Signed-in thumbnail reads went through cookie/session refresh; favicons also matched the proxy | Skip session work only for GET/HEAD on the exact existing public UUID-thumbnail pattern. The two exact favicon paths skip the matcher. Malformed/private image paths, other APIs and protected pages retain interception. Upload authorization and thumbnail validation are unchanged.                                                       |
| Non-billing dashboard        | Every view awaited and serialized full order history                                           | Courses/Explore/Account receive an owner-scoped exact count, not financial history. Production uses one `HEAD` count query instead of the legacy/current full-history reads; local demo uses a parameterized count query. Opening Billing fetches current details.                                                                           |
| Billing entry                | Server loaded history and client immediately fetched it again                                  | Billing deep links use the fresh server snapshot once. Pending supported payments are still checked immediately. Focus, manual refresh and reopening Billing read current history, not the old initial snapshot. Deferred first loads show placeholders, not a false empty history.                                                          |
| Billing polling              | Every supported-provider status check reread complete history                                  | Keep five-second status checks, rotating four-order batches and the 40-check bound. Full history is read every 30 seconds, on terminal status, focus/manual refresh, or reopening. Pending UPI/other providers still reread every five seconds. A focus refresh received during an in-flight check is queued once.                           |
| Announcements                | Fresh server announcements were immediately fetched again                                      | Reuse even an empty supplied snapshot. Refresh visible stale snapshots at most once a minute; refresh immediately if none was supplied. Focus/visibility events coalesce, hidden pages pause network work, failures keep confirmed notices, and unmount/prop changes discard obsolete responses. Ticker animation code/styles are unchanged. |
| Deep links/history           | Existing tab aliases and destination state had inconsistent handling                           | Preserve Billing/Orders, Courses/Study and Account/Profile/Devices aliases; normalize history restoration. Explicit Explore now opens Explore even for enrolled users. New server destination props reset the matching dashboard instance.                                                                                                   |
| Activity update              | Admission plus a conditional five-minute update                                                | **Kept unchanged intentionally.** Combining them needs a versioned SQL RPC and transactional verification; this phase does not remove security/activity work merely to save a request.                                                                                                                                                       |

Course catalogue reads remain because navigation/course counts and switching views use them. Scoped catalogue SQL, pagination and other Phase 4 database/reporting work were not pulled into this batch. No animation, visual stylesheet, financial snapshot or settlement rule was removed.

## Request-chain audit (P3.1)

These chains are source-traced; they are not a newly captured browser network trace. Before-work baseline was commit `6974c8c`, with **152 component tests and 62 backend/asset tests passing**.

| Entry                     | Required chain retained                                                                                                                                          | Duplicate removed                                                                                               |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Anonymous public page     | Proxy without session cookies skips refresh → provider `/api/auth/me` → endpoint rejects missing identity → anonymous display state                              | Consumers share the provider's request; no cookie introspection in the browser.                                 |
| Signed-in public page     | Proxy refresh → provider request with its own proxy/endpoint verification → shared display state                                                                 | Multiple UI consumers do not create independent identity reads.                                                 |
| Signed-in admin           | Page proxy → shared `/api/auth/me` → provider state → staff/MFA UI gate → selected-panel API with independent server authorization                               | Previously both provider and admin mount issued `me`; now admin uses the same result.                           |
| Signed-in student         | Page proxy → server admission → parallel catalogue, count or required history, announcements → dashboard; provider separately verifies display/session freshness | No unrelated full-history read on non-billing entry; no immediate duplicate announcement read.                  |
| Protected API             | Proxy refresh where applicable → endpoint verified identity → admission/revocation → required role/MFA/owner check → response                                    | These independent authorization boundaries were **not** replaced with browser state or a global identity cache. |
| Public thumbnail GET/HEAD | Exact UUID pattern → existing thumbnail route validates width/ID → public immutable image response                                                               | Session refresh skipped; no other API exemption.                                                                |

Identity itself still verifies `getUser`, the associated token/session, email verification and the authoritative profile/block flag. Admission still checks `auth_has_session`, device limits/revocation and activity. The provider is display state, never server authorization.

## Freshness and isolation policy

- Identity: fresh request on pathname change, window focus or explicit refresh. Query-only tab changes share the current identity; protected data endpoints still authorize every request. Same-path concurrent reads coalesce. No reusable-value TTL, local-storage identity, process-global identity map or public private-data cache was added.
- Login/logout: form session-changing redirects notify other tabs; successful logout clears state and notifies. OAuth/full-document redirects get a new provider and fresh identity; returning tabs also refresh on focus. No token or profile is included in the notification.
- Invalidation: a cross-tab signal cancels the relevance of old requests immediately. Unknown/changed account state hides old student data; successful verification either restores the matching account or refreshes server props. Account/destination keys reset component state rather than carry private snapshots into another account.
- Server identity: render-pass scope only. Auth Route Handlers/ordinary calls still reverify; unit tests confirm separate ordinary calls observe a newly blocked profile. Hosted multi-request isolation remains a manual/provider gate, not a claimed live measurement.
- Announcements: 60-second visible-page freshness, no immediate client fetch for supplied server snapshots, abort/ignore obsolete responses, preserve last good data on failure.
- Billing: server snapshot used once; supported pending statuses every five seconds; full-history refresh targets 30 seconds during healthy visible-page polling (network latency/errors can extend actual freshness). Focus/manual/reopen/terminal results force a history read. UPI/other pending providers retain five-second history reads. Paid state/receipts require the saved authoritative order, never a browser payment claim. Guards still stop overlap, hidden-tab work, obsolete updates and unlimited background polling.

## Browser checklist for you

Use a test account/course and your normal app. Restart its server if configuration has not reloaded. Use the same viewport/throttle and a production build for meaningful timing comparisons; development compilation is not production latency.

1. **Identity requests:** sign in as admin, open DevTools Network, clear it and reload. Confirm one client `/api/auth/me` request shared by header/admin. Switch tabs and return to confirm fresh identity. Check support sees only permitted sections, and a student cannot use staff controls.
2. **MFA/device/session fences:** use test accounts to check authenticator-required, device-limit, expired/revoked and blocked-account states. Do not bypass MFA or alter a live user's session just for testing. Confirm staff panels disappear after failed revalidation and permitted recovery paths still work.
3. **Account switching:** keep two tabs open. Sign out in one; the other must hide previous-account dashboard data. Sign in as a different test user and return; verify their name, courses, order badge, billing, notes and devices contain no data from the earlier account. Repeat with a delayed identity request.
4. **Destinations/back navigation:** visit Courses, Explore, Billing and Account; use browser Back/Forward. Also check `/dashboard?view=explore`, `?tab=orders`, `?tab=study`, `?view=profile`, `/dashboard/orders` and a saved course/lesson deep link. Refresh each selected destination and confirm the correct screen, counts and error/retry controls.
5. **Billing:** open a non-billing view first, then Billing. It should load current history and the exact count. Reload a billing deep link: supplied history should appear without an immediate duplicate full-history request. Manual refresh and leaving/reopening Billing must fetch current data.
6. **Payment-app return:** with a test pending order, leave for the payment app/sandbox and return while a status request is slow. Confirm a fresh history read occurs, saved paid state appears, receipts stay unavailable until confirmed, and errors never suggest paying twice. UPI pending orders must retain their existing update cadence. Do not initiate a live charge solely to test this optimization.
7. **Polling/hidden tabs:** inspect requests for a pending supported-provider fixture: status checks every five seconds; history every 30 seconds unless forced. Hide the tab; it should stop starting new billing/announcement network work. Return and confirm immediate billing refresh. Check manual retry after an error and that completed/no-pending history does not poll indefinitely.
8. **Announcements:** with a supplied server snapshot, no immediate client announcement request should follow hydration. Publish/change a test notice and confirm it refreshes in about a minute or on returning after it becomes stale. Pause/resume ticker and verify its animation is unchanged.
9. **Public/private resources:** with a signed-in test account, check thumbnail URLs still return correctly sized cached images. Private APIs, lesson content, receipts and staff mutations must still reject unauthorized users. Check both themes/favicons.
10. **Timing comparison:** capture the same signed-in navigation sequence/settings as the Phase 0-1 baseline, including a cold and returning visit. Compare request counts, payload sizes and median/p95 timings; report slow cases rather than assuming the local fixture reduction applies everywhere.
